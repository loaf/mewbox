# 喵盒 MewBox 总体开发路线图（M1–M5）

> **For agentic workers:** 本文件是总体路线图与里程碑验收门。每个里程碑开工前，先依据本图写出该里程碑的详细实施计划（见 `writing-plans` 技能），存于本目录；执行使用 `executing-plans` 或 `subagent-driven-development` 技能。

**Goal:** 按 DESIGN.md v1.1 交付本地优先个人写作工作台——Markdown 文稿 + 发布版本 + 知识库 + 无状态 AI 工具层。

**Architecture:** Tauri 2（Rust：文件/索引/FTS/LLM/SSE）+ React + TypeScript + Tailwind 前端；工作区目录自包含（posts/ + kb/ + _assets/ + .versions/ + .index/），SQLite 索引可随时重建。

**Tech Stack:** Tauri 2、React 18 + TS、Tailwind、@uiw/react-md-editor、rusqlite(FTS5)、jieba-rs、reqwest(SSE)。

**规格来源：** `DESIGN.md`（v1.1，已经 `DESIGN-REVIEW.md` 两轮 26 条裁定）；UI 视觉基调见 `prototype/css/style.css`（暖米白 `--bg:#f6f1e8` + 蓝灰猫 `--cat:#6f7787` + 纸箱 `--box:#c79a63`，M1 起直接沿用其设计令牌与三栏骨架）。

## 工作约定（贯穿所有里程碑）

1. **仓库**：`X:\proj\myaikl` 执行 `git init`；每个里程碑一条分支 `m1`…`m5`，合入 `main` 前需过验收门。
2. **测试节奏（TDD）**：纯逻辑（Rust 模块 / TS 工具函数）一律先写失败测试再实现；UI 组件用 Vitest + Testing Library 覆盖渲染与交互（mock Tauri invoke）；每个任务一个 commit。
3. **每里程碑三类验证**：
   - 自动化：`pnpm check`（tsc 类型检查 + vitest；M1 起不引入 eslint，如后续引入则更新口径）与 `cargo test --all` 全绿；
   - 构建：`pnpm tauri build` 产出 Windows 安装包（每个里程碑 = 一个可安装的桌面应用，DESIGN §12）；
   - 人工：按该里程碑的 QA 清单逐项打勾（清单写入该里程碑计划文档）。
4. **确认门**：里程碑完成并验证后，向用户提交验收摘要（功能清单 + 测试结果 + 已知问题），**用户确认后才进入下一里程碑的计划撰写**。
5. **范围纪律**：backlog 项（DESIGN §12）不做；发现设计缺口记入 `docs/decisions-log.md` 并在确认门提出，不擅自扩大范围。

### M1 能写作（详见 m1 计划）

- 范围：Tauri 骨架 + 三栏布局 + 工作区初始化（锁）；编辑器（三模式 + 渲染扩展 + 自动保存）；历史（快照/diff/恢复/里程碑/清理）；虚拟目录树（folder 聚合/拖拽/未分类）；列表状态过滤与时间排序（§4.3，标签过滤随 M5）；回收站；索引 + FTS5 + jieba 基础设施；附件池（贴图去重）。
- 测试重点：frontmatter 往返与透传；快照命名与保留策略（48h/日/周/里程碑）；虚拟目录聚合与改名批处理；FTS 中英混排检索；回收站 30 天清理连带 `.versions/{id}/`；附件指纹去重与相对路径重算。
- 验收门：自动化全绿 + 安装包 + QA 清单（约 20 项）+ 拷走工作区目录可重开（「拷走即迁移」冒烟）。

### M2 能发布

- 范围：发布目标注册表（config.toml）；从文稿或指定历史版本创建发布版本（正文相对引用重写）；版本编辑（归属横幅）+ 独立历史；入口（文稿菜单 + 尾部关联块「发布版本」区，但 M2 尚无关联块体系——**按依赖调整为：文稿菜单 + 版本编辑器「回到母版」**，关联块区随 M3 落地后补挂）；发布记录回填。
- 测试重点：创建版本时附件/相对链接重算正确（从 `.versions/{id}/publish/` 出发指向真实文件）；同步前自动快照进**版本自身**历史；一目标一版本约束；`base`/`forked_from` 归属字段；母版改动不影响版本、反之亦然。
- 验收门：自动化全绿 + 安装包 + QA 清单（多渠道分叉/同步/记录闭环）。

### M3 有知识库

- 范围：kb 物理目录树 + 资料编辑（历史，Inbox 亦开）；md 导入（结构保留、frontmatter 透传）；非 md 文件容器化导入；尾部关联块双侧同步；正文 wiki 链接（title 解析、重名悬空待选定）+ 反链面板；关联管理 UI；资料⇄文稿互转（id 不变、历史随行、关联保留）；应用内移动/重命名引用同步；健康检查（断链/孤儿历史/无主版本/孤儿附件，回收站目标不计断链）。
- 测试重点：关联块双侧同步与相对路径重算；title 变更同步更新全部 `[[旧标题]]`；重名链接悬空与候选固定；跨库互转后 id/历史/关联完好；移动后所有引用（正文链接 + 关联块双侧）原子更新；健康检查四类检出与一键修复。
- 验收门：自动化全绿 + 安装包 + QA 清单 + 「裸读文件即可见关联」抽查。

### M4 有 AI

- 范围：providers/路由/钥匙串/预算 + ai_calls 留痕 + 用量面板；AI 工作台（混合多选、总结/提取/翻译/对比/问答/附件描述/自定义、结论存为资料含溯源）；选区工具条；全文润色建议与查错面板（逐条采纳）；快捷搜索资料（FTS 复用，默认仅知识库）。
- 测试重点：任务路由表与 fallback；SSE 流式解析（分块/半行/多事件）；预算超限熔断；ai_calls 字段完整性与「不作为上下文」；存为资料的 `source: ai-workbench` + `generated_from` + 可选关联写入；采纳 = 普通编辑照常进历史；发布版本编辑器内结果不写回母版；LLM 层用本地 mock server（不依赖外网与真实密钥）。
- 验收门：自动化全绿（含 mock LLM 端到端）+ 安装包 + QA 清单 + 内容出站提示抽查。

### M5 好检索好迁移

- 范围：全局搜索 UI（FTS5 + jieba，中英混排，可选含发布版本）；标签过滤（§4.3 在 M1 未尽的列表过滤部分）；Markdown 导入导出（目录 + frontmatter 透传 + 附件随行）；单文稿打包导出（正文 + 引用附件 + 历史 + 发布版本，包内引用重写）；附件指纹去重完善、忽略规则。
- 测试重点：搜索结果排序与范围开关；导入导出往返无损（含附件与中文文件名）；zip 包在任意位置解包后引用有效；孤儿附件清单与确认清理。
- 验收门：自动化全绿 + 安装包 + QA 清单 + 「拷走即迁移」全量演练（新机器/新目录重开）。

## 依赖与风险备忘

- M4 快捷搜索依赖 M1 的 FTS 基础设施（已在 M1 落地）；M4「存为资料并关联」依赖 M3 关联块。
- M2 的「尾部关联块发布版本区」实际挂接点在 M3（关联块体系落地时），M2 计划中已注明。
- jieba 词典加载较慢（首帧卡顿风险）：M1 计划中用懒加载 + 后台预热处理。
- Windows 路径/大小写与 CRLF 是长期坑：M1 的 frontmatter 与扫描模块测试显式覆盖 CRLF 与同名不同子目录。
