# M2「能发布」实施计划

> **For agentic workers:** 使用 `executing-plans` 技能执行。步骤用复选框跟踪。前置阅读：DESIGN.md §3.2（发布版本 frontmatter）/§5（发布版本全章）/§12 M2；`2026-08-18-mewbox-roadmap.md` M2 节。已获用户授权：计划评审通过后直接执行，里程碑结束再验收。

**Goal:** 多渠道发布工作流闭环——从文稿创建发布版本（物理隔离于 `.versions/`、不进侧栏）、独立编辑与历史、从母版同步（先快照）、发布记录回填。

**Architecture:** Rust 新增 `publish.rs`（版本元数据/IO/链接重写）+ `config.rs`（config.toml 目标注册表）；`history.rs` 的快照函数泛化出「指定目录」版本供 `{target}.history/` 复用；命令层沿用 AppState 模式。前端 store 增加「版本编辑态」，EditorPane 以 mode 区分文稿/版本（横幅归属、回到母版），发布面板与同步对话框为新组件。

**Tech Stack:** 同 M1；新增 `toml` crate。

**关键设计约束（来自 DESIGN §5/§13 决策 8/9）：**
- 发布版本**不进左侧列表**（`.versions/` 物理忽略即 UI 忽略）；入口只有文稿菜单、版本编辑器「回到母版」（关联块「发布版本」区随 M3 落地）。
- **一目标一版本**：`{target}.md` 已存在即报错；重发用新目标名。
- 归属由 frontmatter `base`（文稿 id）表达，**不用尾部关联块**。
- 创建/同步时**重写正文相对引用**（指向真实文件，零锁定不变）。
- 同步覆盖前**自动快照进版本自身** `{target}.history/`（DESIGN-REVIEW 二轮 10）。
- 母版与版本互不影响：各自文件、各自历史。

### Task 2: history.rs 快照目录泛化（先于 publish IO，供其复用）

**Files:** Modify `src-tauri/src/history.rs`

目录来源参数化（恢复/读快照/里程碑同样需要目录版——版本历史的快照在 `{target}.history/`）：

```rust
pub fn write_snapshot_in(ws, dir: &Path, idx, file_id, content) -> Result<SnapshotEntry>
pub fn list_snapshots_in(ws, dir: &Path, idx, file_id) -> Result<Vec<SnapshotEntry>>
```

### Task 3: 相对链接重写（纯函数）

**Files:** `publish.rs` 内 `pub fn rewrite_relative_links(body, from_dir: &str, to_dir: &str) -> String`

规则：逐个 `[text](dest)`；跳过 `http(s)://`、`#`、`mailto:`、`data:` 开头；**dest 先剥掉 `#fragment` 与 `?query` 再解析、重算后拼回**；`from_dir` 解析 dest → 工作区根相对路径 → 按 `to_dir` 用 pathdiff 重算（`/` 分隔）。`<img src>` 与根相对 `/x` M2 不处理（记入已知限制）。

- [ ] 失败测试：
  - `posts` → `.versions/{id}/publish`：`![](../_assets/a.png)` → `![](../../../_assets/a.png)`
  - 嵌套文稿 `posts/2026` → publish：`../../_assets/a.png` → `../../../_assets/a.png`
  - http 链接与页内锚点原样；`[文本](../kb/x.md)` 同样重算
  - `a.md#sec` / `a.md?q=1`：路径部分重算、fragment/query 原样保留
  - 代码围栏内的 `[x](y)` 不改（跳过 ``` 围栏行之间的内容）
- [ ] 实现使测试通过。

### Task 4: publish.rs IO

**Files:** `publish.rs`

路径约定：版本文件 `ws.root/.versions/{base}/publish/{target}.md`；版本历史 `{target}.history/{ts}-{hash8}.md`。

- `create_version(ws, idx, base_id, from_content: &str, from_dir: &str, target, forked_from: Option) -> Result<VersionSummary>`：已存在同目标 → `PublishError::TargetExists`；重写链接；写文件（frontmatter + 重写后正文）；索引登记。
- `list_versions(ws) -> Vec<VersionSummary>`（扫 `.versions/*/publish/*.md`，磁盘为准）；`read_version` 返回 fm + body。
- `save_version(ws, idx, base_id, target, body)`：正文实质变化才快照进 `{target}.history/`（Task 2 的 `write_snapshot_in`，file_id 用版本 UUID）；bump updated；原子写；索引更新。
- `restore_version_snapshot` / `set_version_milestone`：Task 2 目录版 + 版本文件为覆盖目标。
- `sync_from_post(ws, idx, base_id, target, post_content, post_dir)`：先无条件快照当前版本完整内容 → 母版正文+重写链接覆盖（保留版本 id/target/base/forked_from，bump updated；published_url/at 独立于同步，保留）。
- `set_published(ws, idx, base_id, target, url: Option, date: Option)`：只改这两个字段；索引 status **由 `published_url.is_some()` 派生**（有 url 即 published）。
- 索引方法：`upsert_publish_row`（kind=publish、folder=None）；`list_publish_by_base(base_id)` 用**路径前缀** `path LIKE '.versions/{base}/publish/%'`（当前 schema 无 base 列，folder 不用）。

- [ ] 失败测试（tempdir + 内存索引）：
  1. `create_writes_rewritten_links`：带 `_assets` 引用的文稿创建 wechat 版 → 版本正文含 `../../../_assets/`；fm 的 base/target/id 齐全
  2. `one_target_one_version_enforced`：同 target 二次创建 → TargetExists
  3. `save_snapshots_into_own_history`：改两次 → `{target}.history/` 出现快照且命名合规；restore/milestone 版本版可用
  4. `sync_snapshots_before_overwrite`：先改版本正文，sync 后正文==母版（链接已重算），旧版本内容进历史
  5. `post_and_version_independent`：改母版不影响版本文件，反之亦然
  6. `set_published_roundtrip`（status 派生）
- [ ] 实现使测试通过。
