# M4「有 AI」实施计划

> **For agentic workers:** 使用 `executing-plans` 技能执行。前置阅读：DESIGN §8（AI 能力全章）、§8.5 留痕、§12 M4、决策 5/6/10/11；§9（快捷搜索复用 FTS）。已获授权：评审通过后直接执行，里程碑结束验收。

**Goal:** 无状态 AI 工具层——模型配置（providers/路由/钥匙串/预算）+ 留痕与用量；AI 工作台（混合多选、总结/提取/翻译/对比/问答/附件描述/自定义、结论存为资料）；写作辅助（选区工具条、全文润色建议、查错面板）；快捷搜索资料。全程人工把关、留痕、可预算。

**铁律（DESIGN §8.1）：**
1. 单次受控调用（固定操作类型 + prompt 模板 + 可选自定义指令）——无 Agent、无循环、无后台。
2. 一切产出先流式预览，**采纳才落盘**；采纳=普通编辑，照常进历史。
3. 无状态：不建记忆；对话上下文仅当次窗口。
4. 每次调用入 `ai_calls`（时间/操作/对象/模型/prompt 摘要/token/耗时/结果去向）；留痕仅审计，不作上下文。
5. 内容出站知情：云模型 UI 明示「将发送至 {provider}」；Ollama = 完全离线。
6. 发布版本编辑器内结果仅本版本，不写回母版（沿用 M2 结果去向）。

## 技术设计

- **LLM 层（llm.rs）**：`ChatRequest { messages, model, params }`；Provider 三实现：
  - `openai`（兼容 API：`POST {base}/chat/completions`，SSE `data:` 行，`choices[0].delta.content`）
  - `anthropic`（`POST {base}/v1/messages`，SSE `content_block_delta`）
  - `ollama`（`POST {base}/api/chat`，NDJSON 行流）
  - 图片消息（视觉）：openai `image_url`(base64 data URL)；anthropic `image` block；ollama `images`(base64 数组)。
  - 统一返回 `impl Stream<Item = StreamEvent { Delta(text)|Done{usage}|Error }>`；流经 Tauri event `ai-stream:{call_id}` 推前端。
- **SSE 解析**：reqwest `bytes_stream()` + 手写行缓冲解析（三种格式各自的增量提取），**不用 eventsource crate**（少依赖，测试可控）。
- **密钥（keyring）**：`keyring` crate 存 Windows 凭据管理器（service=mewbox, user=provider_id）；**不落盘、不进工作区**；换机需重配（设计如此）。
- **config.toml [ai]**：`[[ai.providers]] id/base_url/type/model`；`[ai.routes] op→"provider:model"` + fallback 链 `[ai.fallbacks]`；`[ai.budget] daily_cents/monthly_cents/paused`。key 永不出现在 config。
- **ai_calls 表**（index.rs）：`id/ts/op/target_ids(json)/model/provider/prompt_digest/tokens_in/out/duration_ms/outcome(preview|adopted|discarded|saved|cancelled|error)`；`usage_stats(period)` 按操作/模型/日聚合。
- **预算（budget.rs）**：调用前检查当日/当月 tokens×单价（单价记在 provider 行：`price_per_1k_in_cents`/`price_per_1k_out_cents`，美分，缺省 0）；超限 → 明确报错（可配 paused 直接禁用 AI）。本地 Ollama 不计费。
- **Prompt 模板（prompts.rs）**：纯函数 `build(op, inputs, custom?) -> (system, user)`——每操作一个固定模板（中文指令），自定义指令附加。**输出协议**：润色/查错要求 JSON（`[{"原段","改段","理由"/"类型","定位","建议"}]`），带「只输出 JSON」约束 + 容错解析（剥 ```json 围栏/尾逗号）。
- **附件描述**：pdf-extract 抽文本（docx 留 backlog）；图片读 `_assets` 文件 → base64 视觉消息；结果写入容器正文并 `source: ai-desc` 标注。
- **Mock 测试**：`tests/` 起 `std::net::TcpListener` 微型 SSE 服务器（分块、半行、多事件）直连 `http://127.0.0.1:{port}`——**不依赖外网与真实密钥**；keyring 在测试环境用内存假实现（feature 或 trait 注入）。
- **快捷搜索**：`search_materials(q)` 复用 FTS（Scope::Materials 新增，仅 kind=material）；前端右栏「资料」页。

## 修订决策（评审后固化）

1. **异步与取消（T0/T6/T8）**：这是首个异步命令——`ai_run_op` 为 `async fn`，内部 `tauri::async_runtime::spawn` 任务并**立即返回**；任务体内**绝不持 `std::sync::Mutex<Index>` 跨 await**（需索引时短锁取数据后释放）。取消：`AppState` 增加 `ai_tasks: Mutex<HashMap<String, tokio::task::AbortHandle>>`（spawn 返回 handle 存入，任务结束/出错/取消时移除）；`ai_cancel(call_id)` → `handle.abort()` → ai_calls 记 `outcome=cancelled`（流事件发 `Error("已取消")`）。依赖补 `tokio-util` 不需要（AbortHandle 方案）。
2. **补命令（T8）**：`ai_discard_result(call_id)`（outcome=discarded）、`ai_test_connection(provider_id)`（发一条 1-token 测试消息）、`ai_save_ai_config(routes/fallbacks/budget/prices)`（config 写回）、`ai_clear_calls()`（§8.5 一键清空）、`ai_delete_key(provider_id)`。每条建议的逐条采纳**不单独立 call**：批量润色/查错整体记一次 `adopted`（部分采纳也算 adopted；采纳计数存 prompt_digest 附注）。
3. **精确替换算法（T12）**：按建议列表**从后往前**采纳（先处理文中靠后的原段，避免位移失效）；匹配 = 在当前正文中查「原段」首次出现；未命中 → 该条跳过并在 UI 标灰「原文已变化」；多处命中取第一处。前后端各测。
4. **选区工具条机制（T11）**：MDEditor `textareaProps` 增加 `onSelect`/`onMouseUp`/`onKeyUp`（复用现有 onPaste 通道拿元素与选区）；浮条定位**锚定鼠标抬起点**（fixed 定位于 clientX/clientY，屏幕边缘翻转）——不做镜像测量。textarea 内多行选区用此简化方案，够用且零依赖。
5. **前端流式（T10-12）**：共享 hook `useAIStream(callId)` 封装 `listen("ai-stream:"+id)`，**先 listen 再 invoke**；call_id 由前端生成（uuid）。T9-T13 每任务附 vitest 清单（照既有 per-component 惯例）。
6. **单位统一（T3/T4/T9）**：预算与价格统一用**美分**（`daily_cents/monthly_cents`，`prices: "per_1k_in_cents/per_1k_out_cents"`），不做美元换算。
7. **版本入上下文（T6/T10）**：工作台上下文条目类型 `{kind: post|material|version, id?, base+target?}`；读内容版本走 `publish::read_version_body(base,target)`。附件描述路由在设置面板路由表标注「需视觉模型」。
8. **Token 估算（T10）**：粗估 `chars/4`（中文按 chars/1.5），与模型上限（provider 配置 `max_context`）比较给分批/截断/换模型提示；预算预估同口径。
9. **AppError 增 AI 变体**；pdf 抽取空文本（扫描件）→ 明确报错「未抽取到文本（扫描件暂不支持）」。
10. **树多选入口不做**（面板内多选已覆盖 §8.2 入口语义），记入不做清单。

- **T0** 依赖：reqwest(rustls,stream)/keyring/pdf-extract/base64/futures-util/tokio-stream；模块骨架。
- **T1 llm.rs SSE 解析器（纯函数）**：`parse_openai_line/parse_anthropic_line/parse_ollama_line(&str) -> Vec<StreamEvent>`；`LineAssembler`（跨 chunk 半行缓冲）。测试：分块/半行/多事件/[DONE]/usage 事件/坏行跳过。
- **T2 llm.rs 客户端**：`stream_chat(provider_cfg, key, req) -> Stream`；**mock SSE 服务器**集成测试（三种 provider 各一：增量序列完整、错误透传、usage 汇总）。key 经 `KeyStore` trait（真实现 keyring / 测试内存）。
- **T3 config + keyring**：`[ai]` 解析/写回（透传保留）；路由解析 `resolve_route(op) -> (provider, model, fallbacks)`；KeyStore 存/取/删。测试：路由+fallback、config 往返、内存 keystore。
- **T4 ai_calls + 预算**：表、record、usage_stats（日/月、按操作/模型）；budget 检查（超限错误、paused 短路、Ollama 免费）。测试含跨日聚合。
- **T5 prompts.rs**：全部操作模板 + JSON 容错解析器 `parse_suggestions/parse_issues`。测试：模板含上下文与自定义指令、围栏/尾逗号/中英混排 JSON 解析。
- **T6 工作台/写作辅助编排（ai.rs）**：`run_op(op, target_ids, custom, call_id, window)`——读内容（文稿/资料全量、附件按勾选）→ 预算检查 → prompt → 流式（event 推送）→ 完成（返回全文+usage，落 ai_calls outcome=preview）；`adopt_*`（insert_at_cursor 由前端执行文本插入，后端只记 outcome）；`save_as_material(text, source_ids, title)`（`source: ai-workbench`+`generated_from`+可选 update_assoc）；附件描述 `describe_attachment(material_id, fingerprint)`。润色/查错：流式收集→JSON 解析→建议列表命令。全部走普通编辑流。
- **T7 快捷搜索**：`search_materials`（Scope::Materials）。
- **T8 commands + 事件**（含修订决策 2 补充命令）：`ai_run_op/ai_cancel/ai_adopt_result/ai_discard_result/ai_save_as_material/ai_describe_attachment/ai_apply_suggestions(润色+查错通用精确替换)/ai_test_connection/ai_list_providers/ai_save_provider/ai_delete_provider/ai_set_key/ai_has_key/ai_delete_key/ai_save_ai_config/ai_usage/ai_clear_calls/ai_search_materials`；lib.rs 注册；流事件 `ai-stream:{call_id}`（润色/查错 JSON 由前端从流中收集，不单独立 call）。

## Chunk 2：前端（任务 9–14）

- **T9 设置面板**：左栏「⚙ 设置」（providers 列表/新增、base_url/model/测试连接；密钥写入钥匙串——输入框不回显；路由表编辑；预算与价格；用量统计图（按日/操作/模型聚合表）；「内容出站」说明区）。
- **T10 AI 工作台**：右栏「AI」页签——上下文多选（文稿+资料混选，含发布版本入口沿用 M2）；操作下拉（总结/要点/翻译/对比/问答（多轮，当次窗口）/附件描述/自定义）；附件原文勾选；「开始」→ 流式预览卡（listen `ai-stream:{id}`）；结果去向按钮组（插入当前文稿光标｜存为资料（弹标题+可选关联）｜复制｜丢弃）；出站提示「将发送至 {provider}」；超长警告（tokens 预估超限→提示分批/截断/换模型）。
- **T11 选区工具条**：编辑器 textarea selectionStart≠End 且鼠标释放 → 浮条（改写/扩写/缩写/改语气/翻译/润色/自定义）；结果预览卡（流式）→ 采纳=替换选区/插入/复制/放弃；发布版本模式下按钮组仅本版本。
- **T12 全文操作面板**：编辑器顶栏「润色建议」「查错」→ 右栏面板：润色分条（原文/改文/理由，逐条采纳=精确替换）；查错分条（类型/定位行/建议，点击跳转行、逐条采纳）。
- **T13 快捷搜索页**：右栏「资料」页签——选词/快捷键(Ctrl+K→聚焦)→FTS 结果（默认仅知识库，可切含文稿）→ 条目按钮「插入链接」（`[[标题]]` 或相对 md 链接）/「添加为关联」（update_assoc）。
- **T14 集成验收**：cargo（含 mock SSE）+ vitest + tsc 全绿；dev 冒烟（Ollama 可选真实连）；build 出包；QA 清单（≥16 项映射 §8）→ roadmap → 验收摘要。
